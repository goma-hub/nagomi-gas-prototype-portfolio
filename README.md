# 和み製菓 営業部 売上報告・集計プロトタイプ

## 概要

架空企業「株式会社 和み製菓」の営業部DX推進計画に基づき、法人向け卸売業務における売上報告・集計・月次報告を自動化するGoogle Apps Script（GAS）のプロトタイプです。

営業担当者がGoogleフォームから売上を報告し、GASがマスタデータを参照して売上金額を計算・記録します。また、蓄積した売上データを月次で集計し、メールで報告する機能を備えています。

本プロトタイプはDX推進計画の一部を対象としており、受注管理・注文確認メールの自動送信・顧客情報の一元管理などは実装対象外です。

## 主な機能

- 売上報告フォームの報告者・取引先・商品の選択肢を、社員名簿と各マスタから手動で更新する。
- フォーム送信時に入力内容とマスタを照合し、商品マスタの標準単価と販売個数から合計金額を計算して9列の売上報告集計シートへ記録する。販売単価と合計金額は記録時の数値を保存する。
- 日本時間の報告日時を基準に月次の売上件数と総売上額を集計する。
- 管理用スプレッドシートのメニューから、対象年月と宛先を指定して月次報告メールを手動送信する。送信前に集計結果を確認し、送信直前に結果が変わった場合は再確認を求める。
- 前月分の集計結果を社員名簿の営業部長へ送る自動送信処理を備える。定期実行の検証状況は「制約・注意事項」を参照。

## システム構成・使用技術

営業担当者のGoogleフォーム送信 → フォーム送信トリガー → GASによるマスタ参照・検証・計算 → Googleスプレッドシートへの記録、という流れです。月次報告はGASが記録済みデータを集計し、MailAppでメールを送信します。

- `gas/Code.js`：フォームの選択肢更新、売上記録、月次集計、メール送信、初期設定
- `gas/ManualMonthlyReport.html`：手動送信の入力・確認ダイアログ
- `gas/appsscript.json`：V8ランタイムと`Asia/Tokyo`タイムゾーンの設定
- `tests/Code.test.js`：Node.jsのテストランナーを用いたローカルテスト

## データ構成

既存のスプレッドシートに次のシートを使用します。見出しは記載順に配置します。

| シート名 | 列 |
| --- | --- |
| 売上報告集計シート（または売上報告集計） | 報告日時 / 報告者名 / 取引先ID / 取引先名 / 商品ID / 商品名 / 販売個数 / 販売単価 / 合計金額 |
| 社員名簿 | 社員名 / 部署 / 役職 / メールアドレス |
| 取引先マスタ | 取引先ID / 取引先名 / 取引先区分 |
| 商品マスタ | 商品ID / 商品名 / 標準単価 |

売上報告フォームは`報告者名`・`取引先名`・`商品名`・`販売個数`の4設問です。取引先と商品は`ID｜名称`形式の選択肢を使い、販売個数は1以上の整数を入力します。販売単価と売上日はフォームで入力しません。月次集計にはフォームの報告日時を使用します。

## セットアップ・使い方

1. 既存の売上管理スプレッドシートに紐づくGASプロジェクトへ、`gas/Code.js`と`gas/ManualMonthlyReport.html`を配置し、`gas/appsscript.json`の設定を反映します。コードはフォームやシートを新規作成しません。
2. 上記のシート名・見出し、社員名簿の営業部員と営業部長、取引先・商品マスタのID、商品マスタの標準単価を確認します。スクリプトプロパティ`NAGOMI_SALES_FORM_ID`に、使用する既存フォームの編集用IDを設定します。
3. フォーム更新では、報告者・取引先・商品がプルダウンになり、販売個数に正の整数の入力制約が付き、既存の`販売単価`設問が削除されます。フォームの回答や共有設定への影響を事前に確認します。スプレッドシートを開き、「営業部ツール > 売上報告フォームの選択肢を更新」を実行し、確認画面で承認します。社員名簿やマスタを変更した後も、このメニューから選択肢を更新します。
4. 必要なトリガーを登録する場合は、フォームが4設問になったことと既存トリガーを確認したうえで、管理担当者のアカウントから`setupProject()`を実行します。この関数はシート・マスタ・フォームを検証し、**不足しているフォーム送信トリガーと月次自動送信トリガーを確認画面で予告してから作成します**。月次トリガーを作成すると、毎月1日9時ごろ（日本時間）に前月分を営業部長へ送る設定になります。現在は月次トリガーを削除済みです。自動送信を有効にしない場合、`setupProject()`を再実行しないでください。別アカウントが作成したトリガーは検出できないため、重複も確認してください。
5. 手動で月次報告を送る場合は、「営業部ツール > 月次報告メールを手動送信」を開き、対象年月を`YYYY-MM`形式で、宛先とともに入力します。「確認」で件数・総売上額を確認し、「送信」を押します。送信直前の再集計で値が変わった場合は、表示された新しい結果を「再確認」してから送信します。売上のない月は0件・0円と表示されます。

## テスト

ローカルテストは`node --test tests/*.test.js`で実行でき、26件成功しています。フォーム・シート・メールなどのGoogleサービスを模擬し、売上記録、マスタと入力値の検証、月次集計、手動送信の確認処理、トリガー設定などをテストしています。

Google環境では、売上報告フォームからの送信と9列への転記・集計、月次報告メールの手動送信を確認済みです。自動送信の定期実行は未検証です。

## 制約・注意事項

- 現在、月次自動送信トリガーは削除済みです。自動送信処理はコードにありますが、定期実行の動作は確認していません。
- 月次集計は売上日ではなく、日本時間の報告日時で対象月を判定します。遅れて報告した売上を元の月へ振り分ける処理はありません。
- 誤報告の訂正や重複登録を管理する専用機能はありません。
- 手動送信は管理担当者の利用を想定しています。コードに独自の認証・権限管理や宛先の登録済みアドレスへの制限はなく、スプレッドシートの共有権限を適切に管理する必要があります。宛先と操作履歴はアプリケーション独自には保存しませんが、Google側の送受信記録などは別です。
- フォーム送信時には未登録ID、マスタと一致しない名称、不正な単価・個数などをエラーにし、売上行の追記にスクリプトロックを使用します。文字列の先頭が`=`の場合は数式として評価されないようにしてから保存します。
