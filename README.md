# 和み製菓 営業部 売上報告・集計プロトタイプ

既存の Google スプレッドシートと売上報告フォームを利用するポートフォリオ用 GAS プロジェクトです。

## 対象のシート

- 売上報告集計シート（または売上報告集計）：`報告日時 / 報告者名 / 取引先ID / 取引先名 / 商品ID / 商品名 / 販売個数 / 販売単価 / 合計金額`
- 社員名簿：`社員名 / 部署 / 役職 / メールアドレス`
- 取引先マスタ：`取引先ID / 取引先名 / 取引先区分`
- 商品マスタ：`商品ID / 商品名 / 標準単価`（税抜の円単位、0以上の整数）

## 売上報告フォームと転記

既存フォームを使い、`報告者名`・`取引先名`・`商品名`のプルダウンと、正の整数を入力する`販売個数`の4設問にします。取引先と商品の選択肢は`ID｜名称`形式です。フォームの`販売単価`設問は削除します。`売上日`の入力はなく、フォームの報告日時を月次集計に使用します。

フォーム送信時には営業部員とマスタのID・名称を照合し、商品マスタの標準単価から合計金額を計算します。販売単価と合計金額を数値として行に保存するため、後からマスタ価格を変更しても既存行は変わりません。未登録ID、古い名称、重複ID、空欄や不正な単価、販売個数の不備はエラーにします。追記時はスクリプトロックを使用します。

## 反映時の手順

1. コピー先GASのスクリプトプロパティ`NAGOMI_SALES_FORM_ID`が、コピー済みフォームの編集用IDであることを確認します。対象シートの名前・見出し、マスタのIDと標準単価を確認します。
2. コードをオンラインへ反映する前に、フォームの設問変更を確認します。報告者・取引先・商品はプルダウンに変わり、販売個数に正の整数制約が付き、販売単価の設問は削除されます。既存の回答やフォームの共有設定への影響も確認してください。
3. 反映後、スプレッドシートの「営業部ツール > 売上報告フォームの選択肢を更新」を実行します。変更内容の確認画面が出ます。社員名簿やマスタの変更後も同じメニューから手動更新します。
4. フォームが4設問になったことを確認した後、同じ管理者アカウントで`setupProject()`を実行します。9列のシート・マスタ・フォームを検証し、不足しているフォーム送信と月次報告のトリガーを予告してから作成します。フォーム、シート、フォルダは作成しません。
5. 既存トリガー、フォームの選択肢・共有設定、転記先、営業部長のメールアドレスを確認します。別アカウントが作ったトリガーは検出できないため、重複に注意してください。

月次報告は毎月1日9時ごろに前月の総売上額と売上件数を社員名簿の営業部長へ送ります。自動送信と手動送信は、日本時間の報告日時（A列）で対象月を選び、合計金額（I列）を合算する同じ集計・本文生成処理を使用します。

## 月次報告メールの手動送信

1. 売上管理スプレッドシートの「営業部ツール > 月次報告メールを手動送信」を開きます。
2. 対象年月を `YYYY-MM` 形式で、送信先メールアドレスとともに入力し、「確認」を押します。
3. 対象年月・送信先・売上件数・総売上額を確認します。売上がない月も0件・0円と表示されます。
4. 「送信」を押すと、送信直前に再集計してから1通送信します。件数または金額が変わった場合は新しい集計結果が表示されるので、「再確認」の後、改めて「送信」を押してください。「キャンセル」は送信せずダイアログを閉じます。送信結果はダイアログ内に表示されます。

対象年月と送信先は毎回入力します。`runEmailDeliveryTest()` は用途が重複するため削除しました。

## セキュリティ・運用上の考慮事項

- 手動送信は営業部の管理担当者が使用する想定です。
- 実行時に指定した送信先や操作履歴はアプリケーション独自の保存領域に記録しません。
- Google側の送受信記録等は保存対象外ではありません。
- 実運用ではスプレッドシートへのアクセスを管理担当者に限定し、必要に応じて送信先を営業部長などの登録済みアドレスに制限します。
- この機能には新たな認証・権限管理を追加していません。
